## 1. 문서 개요 (Document Overview)

### 1.1 배경 및 현황

국문 서비스와 영문 서비스의 메뉴 구성에 격차가 있어 외국인 이용자가 교육·도서관 등의 정보에 접근하기 어렵습니다.

| 분석 영역 | 국문 서비스 | 영문 서비스 | 격차(Gap) |
| :--- | :--- | :--- | :--- |
| 1차 대메뉴(GNB) | 7개 (관람, 전시, 교육, 문화 프로그램, 라이브러리·소장품, 소식·홍보, 미술관소개) | 4개 (Visitor Info, Exhibitions, News/PR, Art Museums) | 대메뉴 3개 누락 (Education, Cultural Programs, Library & Collection) |
| 2차 서브메뉴 | 하위 메뉴 제공 (교육·문화 프로그램은 현재 하위 메뉴 없음) | 대메뉴별 2~5개 제공 | 서브메뉴 6개 누락 (Group Tour Reservation, Membership Info, Online Exhibition, Newsletter, FAQ, Survey). 국문 하위 메뉴가 없는 항목은 이번 작업에서 국문도 함께 정합화 |
| 시각적 가독성 | 불투명 단색 배경 | 메가메뉴 배경이 반투명하여 배경 배너 글자와 겹침 | 글자 겹침으로 가독성 저하 |
| 브랜드 일관성 | 심볼 Fill 타입 로고 | 영문 로고 Line 타입, 영문 명칭 표기 오기(`Suwon Museum Of Art`) | 로고 타입 불일치, 전치사 대문자 표기 |
| 유틸리티·레이어 | 헤더 우측 상단 유틸리티 제공 | 언어 선택 드롭다운이 선택 후에도 열려 있음 | 레이어 자동 축소 미흡 |
| 모바일 탐색 | 전체 메뉴(Drawer) 제공 | 전체 메뉴 열림 시 닫기(X) 버튼 없음 | 메뉴에서 빠져나오는 경로 부재 |
| 접근성 기본 항목 | 푸터 아이콘 `alt` 누락, 링크 이름 누락, `main` 영역 없음 등 | 모바일 푸터 메뉴 글자 대비 부족, 언어 선택 라벨 없음, 구독 버튼 터치 영역 부족 등 | 두 서비스 모두 확대 차단 (1.6 참조) |

**테마별 구조화**

1. **[최우선] 정보 구조 및 다국어 서비스 동등성** (P1)
2. 시각적 가독성 및 명도 대비 (P2)
3. 로고 및 브랜드 표기 일관성 (P3)
4. 헤더 유틸리티 구성 및 레이어 제어 (P4)
5. 모바일 환경 탐색 자유도 (P5)
6. 웹 접근성 기본 준수 (P6)

### 1.3 목적 및 목표

- **목적**: 외국인 방문객이 국문 이용자와 같은 정보에 접근하도록 영문 서비스의 정보 구조를 국문과 동등하게 맞춘다.
- **목표**
  - 영문 GNB를 7개 대메뉴와 하위 메뉴 구조로 복원하고, 국문 메뉴도 같은 구조로 정합화한다.
  - 영문 메가메뉴의 가독성을 개선한다.
  - 언어 선택 레이어와 모바일 메뉴의 이탈·복귀 경로를 개선한다.
  - Lighthouse 자동 검사에서 확인된 접근성 기본 항목을 개선한다.
  - 외국인 방문객이 원하는 정보에 **2~3클릭, 15초 이내**로 도달하고, 과업 성공률 100%, 탐색 오류 0회를 달성한다.

### 1.4 핵심 가설 및 벤치마킹

**가설**: "영문 사이트에 국문과 1:1로 대칭되는 7개 대메뉴 및 하위 메뉴 구조(IA)를 복원하고, 데스크톱 1200px 12-Column 그리드와 모바일 360px 환경에 맞춰 가독성·비상 탈출 경로를 개선하면, 외국인 방문객(Persona 1: Emily)이 원하는 관람·전시·교육 정보에 2~3클릭(15초 이내)으로 도달하고 과업 성공률 100%, 탐색 오류 0회를 달성할 것이다."

## 3. 핵심 사용자 여정 (Core User Journey)

### 3.1 주 흐름 — PC (Persona 1: 교육·도서관 정보 확인 및 신청)

```text
[1] 메인 화면 접속 → 헤더에서 언어를 English로 선택
        ↓
[2] 영문 GNB에서 7개 대메뉴를 확인 → Education 또는 Library & Collection에 마우스 호버
        ↓
[3] 메가메뉴(불투명 패널)에서 Programs & Workshops 또는 Art Library 클릭
        ↓
[4] 목록 화면에서 영문 지원 태그·일정·신청 상태 확인 → 상세 페이지 이동
        ↓
[5] 상세 하단의 Apply / Register 클릭 → 신청 폼 작성 → 제출 → 완료
```

### 3.2 주 흐름 — 모바일

```text
[1] 영문 메인 접속 → 상단 헤더(메뉴 버튼, 로고, 검색, 언어) 확인
        ↓
[2] 메뉴 버튼 클릭 → 전체 메뉴(Drawer) 열림 (상단에 닫기 X)
        ↓
[3] 대메뉴(Education 등) 펼침 → 하위 메뉴 선택
        ↓
[4] 목록·상세 확인 → Apply / Register → 신청 폼 제출
```

| 단계 | 개선 전 (As-Is) | 개선 후 (To-Be) |
| :--- | :--- | :--- |

### 5.2 시각적 우선순위

- GNB 7개 대메뉴는 한 줄로 상시 노출해 정보 구조를 한눈에 파악하게 한다.
- 메가메뉴는 하위 메뉴 전체를 한 번에 펼쳐 비교할 수 있게 한다.
- 호버·키보드 포커스 시 해당 메뉴에 밑줄과 색상 변경으로 현재 위치를 표시한다.
- 서브 화면의 LNB에서는 현재 위치 항목을 시각적으로 강조한다.

### 5.4 접근성 및 준수 기준

- 텍스트 명도 대비 4.5:1 이상 (KWCAG 2.2). 영문 메가메뉴는 불투명 단색 배경으로 해결.
- 메뉴의 비활성 회색 글자는 Figma 값(`#888780`, 흰 배경 대비 3.6:1) 대신 `#5f5e5a`(토큰 `--color-page-container-text-address`, 대비 6.5:1)를 사용한다. 적용 대상: 사이드메뉴_상위메뉴·사이드메뉴_하위메뉴 "비활성화", 상위메뉴 "논클릭". 이후 다른 컴포넌트에서 글자색으로 `#888780`(`Text_under`, `Buttons/Stroke` 등)이 나와도 같은 토큰으로 바꿔 사용한다. 테두리·선 색으로 쓰인 `#888780`은 바꾸지 않는다.
- 모바일에서 확대(핀치 줌)를 막지 않는다.
- 이미지에는 대체 텍스트, 링크와 입력 요소에는 이름(라벨)을 제공한다.
- 모바일 터치 대상은 최소 44px(2.75rem) 이상으로 설계한다 (5.6). Lighthouse 통과 기준은 24×24px이다.
- 키보드 Tab 포커스 시에도 마우스 호버와 같은 시각 표시를 제공.
- 모바일 메뉴는 닫기 경로를 제공 (Nielsen #3).
- 디지털 정부 UI/UX 가이드라인의 메뉴 동등성, 드롭다운 상호작용 원칙을 따른다.

### 5.6 반응형

> 이 절에는 반응형 공통 기준만 정리합니다. **화면별 세부 레이아웃은 구현 단계에서 사이즈별 Figma 링크를 전달받은 뒤 반영합니다.**

**반응형 기준**

- 모바일 우선(Mobile First)으로 작성하고, 미디어쿼리는 `min-width` 기준으로 확장한다.
- 브레이크포인트는 아래 2단계만 사용한다. 태블릿 구간은 따로 두지 않으며, 768px 이상은 데스크톱 기준을 따른다.

| 구간 | 뷰포트 | 디자인 기준 너비 | 적용 방식 |
| :--- | :--- | :--- | :--- |
| 모바일 | 0~767px | 360px | 기본 스타일 (미디어쿼리 없음) |
| 데스크톱 | 768px 이상 | 1920px | `@media (min-width: 768px)` |

**타이포그래피**

- 폰트 크기는 `rem`으로 지정한다.
- 모바일과 데스크톱은 브레이크포인트 기준으로 단계별 크기를 각각 지정한다. 단계별 값은 Figma 전달 후 확정한다.
- 768px~1919px 구간은 1920px 디자인을 화면 전체 비례 축소(글자·간격·크기를 같은 비율로, CSS `zoom`)로 보여 주므로, 이 구간에는 개별 폰트 크기를 따로 지정하지 않는다.
- 비례 축소 규칙 (B-18 해소)
  - 축소 비율 = 화면 너비 ÷ 1920
  - 최소 70%: 약 1344px 이하 화면은 70%에서 멈추고, 공간이 부족하면 카드 열 수 등 배치가 바뀐다. 이때 본문 17px은 약 12px로 보인다.
  - 1920px 이상은 100% (확대하지 않음)

**공통 처리**

- 이미지와 미디어는 `max-width: 100%`로 부모 너비를 넘지 않게 한다.
- 모바일에서 버튼·링크 등 터치 영역은 최소 44px(2.75rem) 이상 확보한다. Lighthouse 통과 기준(24×24px, 6.2 P6)보다 높은 이 프로젝트의 설계 기준이다.

**디자인 전달 방식**

- 반응형 상세 디자인은 구현 단계에서 사이즈별 Figma 링크로 전달한다.
- PRD에는 위 기준만 정리하고, 화면별 세부 레이아웃은 Figma 전달 후 반영한다 (B-19).
